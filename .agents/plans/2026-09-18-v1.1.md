# AI-Graded Apple Interview Practice App

## Summary

Build a Vue flashcard-style interview coach deployed on Vercel’s free tier. The user selects a category or mixed session, records a spoken answer, and receives coaching-first AI feedback.

Each practice cycle will be:

1. Present the question and expected answer time.
2. Record up to two minutes of audio.
3. Transcribe and evaluate the answer server-side.
4. Show strengths, missing story beats, one priority improvement, a model response, and a secondary rubric score.
5. Let the user record another attempt or continue.
6. Save the transcript, feedback, and progress locally; never retain the audio.

Protect the application with a private app password so strangers cannot consume the user’s OpenAI credits.

## Question Deck

Create 20 questions in six categories:

- Personal narrative and motivation
  - Tell me about yourself.
  - Why Apple?
  - Why Wallet, Payments & Commerce?
  - Why return from independent product building to a large engineering organization?

- Product ownership and Sway
  - Tell me about something you built end-to-end.
  - How did user feedback change Sway?
  - What did shipping your own product teach you?

- Leadership and collaboration
  - Tell me about a disagreement with another engineer.
  - Describe a technical decision where you changed your mind.
  - How do you balance engineering quality with delivery pressure?

- Production engineering and reliability
  - What is the hardest technical problem you have solved?
  - Tell me about a production issue you debugged.
  - How do you handle an external-service failure?
  - How do you prevent duplicate or ambiguous payment operations?

- Frontend, API, and system design
  - Design an API between a transaction UI and its backend.
  - How do you approach frontend performance?
  - How would you test a payment-related system?
  - Design the high-level architecture for Sway.

- Vue and team fit
  - How do your React and Next.js skills transfer to Vue?
  - Why might a payments team choose Vue instead of Next.js?

Each card will define expected story beats, a 45–120 second target, a sample response, a likely follow-up, and explicit placeholders where real Capital One details are still needed.

## AI Evaluation

Use `gpt-transcribe` for speech-to-text and the Responses API with `gpt-5-mini` for grading. The latter is appropriate for a well-defined, cost-sensitive rubric and supports structured output. [Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) [GPT‑Transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe) [GPT‑5 Mini](https://developers.openai.com/api/docs/models/gpt-5-mini)

Grade the transcript against question-specific expected beats and six anchored dimensions:

- Relevance: directly answers what was asked.
- Structure: has a clear opening, progression, and conclusion.
- Specificity: uses concrete circumstances, actions, and outcomes.
- Ownership: distinguishes the candidate’s contribution.
- Judgment: explains decisions, tradeoffs, and lessons.
- Clarity: concise, understandable, and free of excessive detours.

Return structured JSON containing:

```ts
interface AnswerEvaluation {
  overallScore: number
  dimensions: {
    relevance: RubricScore
    structure: RubricScore
    specificity: RubricScore
    ownership: RubricScore
    judgment: RubricScore
    clarity: RubricScore
  }
  strengths: string[]
  missingBeats: string[]
  priorityImprovement: string
  improvedOutline: string[]
  followUpQuestion: string
}
```

Each dimension uses a 1–5 score with a one-sentence justification. The interface leads with coaching and keeps the numeric score visually secondary. A score is guidance, not an authoritative hiring prediction.

Calculate duration and words per minute locally and provide a neutral pacing note. Do not claim to grade vocal confidence, tone, pronunciation, or body language because the evaluation model receives the transcript rather than the original audio.

## Server and Security

Add Vercel serverless endpoints:

- `POST /api/session` validates `APP_PASSWORD` and issues a signed, secure, HTTP-only session cookie.
- `DELETE /api/session` clears that cookie.
- `POST /api/evaluate` requires a valid session, accepts one compressed audio recording, transcribes it, grades the transcript, and returns the transcript plus structured evaluation.

Server behavior:

- Read `OPENAI_API_KEY`, `APP_PASSWORD`, and `SESSION_SECRET` exclusively from Vercel environment variables.
- Never expose the OpenAI key through a `VITE_*` variable or client response.
- Keep audio in memory only for the duration of the request and discard it after transcription.
- Set the Responses API request to avoid retaining evaluation responses where supported.
- Enforce audio MIME types, a two-minute recording limit, a conservative upload-size limit, bounded output tokens, and schema validation.
- Apply per-session/IP request throttling and return clear retry guidance.
- Reject unauthenticated, malformed, oversized, or empty submissions before invoking OpenAI.
- Never commit `.env` files; provide `.env.example` containing variable names only.

The user will add credentials directly to local environment settings and Vercel’s secret configuration, not paste them into chat.

## Client Experience

- Replace the starter screen with login, category library, active interview card, recording state, evaluation result, and progress summary.
- Support category practice, shuffled mixed sessions, and “Practice weak answers.”
- Show recording permission and microphone errors with recovery instructions.
- Permit transcript editing before a retry evaluation so transcription mistakes do not permanently distort feedback.
- Save transcripts, evaluations, confidence ratings, and card history in `localStorage`.
- Never save audio recordings.
- Add controls to delete one attempt or clear all local practice history.
- Use one purposeful reveal transition, visible keyboard focus, semantic status announcements, mobile layouts, and reduced-motion support.
- Preserve self-confidence as a separate “How did that feel?” rating rather than blending it into the AI score.

## Test Plan

- Unit-test rubric parsing, weighted scores, question-specific grading payloads, progress calculations, weak-card selection, and local persistence.
- API-test password validation, secure cookies, authorization, file validation, rate limiting, OpenAI failures, malformed model output, and audio disposal.
- Mock OpenAI responses in automated tests; tests must never spend API credits.
- Component-test microphone denial, recording lifecycle, loading, coaching display, retry, and clearing history.
- Cypress-test login → record/mock evaluation → review coaching → resume saved progress.
- Run `npm run test:unit -- --run`, `npm run build`, and relevant Cypress coverage before deployment.

## Assumptions

- This is a private, single-user application deployed to Vercel.
- Audio is discarded after each evaluation; transcripts and feedback stay only in the browser.
- There is no database, account system, cloud answer history, or audio playback archive.
- Grading assesses interview-answer content and structure, not whether a technical claim is factually true when it depends on undisclosed personal experience.
- Guided placeholders remain visible until the user supplies accurate details.
- The `openai-docs` skill determined the current API approach; the `frontend-design` skill guides the cue-card interaction and restrained animation system.
